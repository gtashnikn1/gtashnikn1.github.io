Port forwarding in Linux and Windows

2025-10-23 · Nikita Diubachev
devops network linux

Foreword

Have you ever worked with a software that for some reason doesn't open connection on all interfaces? I guess no, but I did. This thing silently opened a localhost API endpoint for it's internal calls, but it was never documented anywhere. While I wish they did so, it didn't really stop me to perform requests there from my main machine, and now I'd like to show you how it can be done with almost no pain.

Instruments

  • Windows system (Windows 11 in my case)
  • Linux system (Ubuntu in my case)
  • Software that creates an endpoint (will provide it here)

For maximum simplicity we will use a python flask app that will give a response to the root page request.

main.py

main.py
from flask import Flask app = Flask(__name__) @app.route("/") def connection_established(): return "you got it!"

Then let's run this and check its connectivity with curl:

shell
$ python -m flask --app main run * Serving Flask app 'main' * Debug mode: off WARNING: This is a development server. Do not use it in a production deployment. Use a production WSGI server instead. * Running on http://127.0.0.1:5000 Press CTRL+C to quit ... $ curl localhost:5000 you got it!

Amazing! We just served our HTTP request and got a proper response for it! But, unfortunately, if we try to connect to it from the other machine, we will not receive anything, as you can clearly see, it's being served on our loopback address. So here is the thing we can do.

Windows

Simply start cmd window with administrative privilege (Win + R and then Ctrl + Shift + Enter) and paste this command:

cmd (admin)
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=5000 connectaddress=127.0.0.1 connectport=5000

And that's it! Now you can try to access your endpoint via your IP-address from the other host, and you should be served well! Now let's see what this line actually does:

netshShort for Network Shell. It’s the Windows command-line utility for viewing and changing network configuration. Every netsh command runs inside that tool.

interfaceThis is the netsh context (a subsection of commands). It tells netsh you want to work with networking interface-related features.

portproxyA feature inside the interface context that implements a port proxy — it listens on a local port and forwards incoming TCP connections to another address/port.

addThe action you’re taking: add a new port proxy rule. (Other actions include delete and show.)

v4tov4The type of proxy: IPv4 → IPv4. It means the proxy listens on an IPv4 address and forwards to an IPv4 address. (There are also v6tov4, v4tov6 variants for mixed IP families.)

listenaddress=0.0.0.0The IP address where portproxy will listen for incoming connections. 0.0.0.0 is the special address that means listen on all IPv4 interfaces (all IPs assigned to the machine).

listenport=5000The port number on which the proxy listens locally. Incoming TCP connections to the machine's (any) IPv4 address on port 5000 will be picked up by this proxy.

connectaddress=127.0.0.1The destination IP address the proxy forwards traffic to 127.0.0.1, where our app is serving requests.

connectport=5000The destination port at connectaddress. So the proxy forwards to port 5000 on 127.0.0.1.

The only con of this is that we can't serve UDP traffic, so if you came here for it, this is not your choice, unfortunately.

Linux

Considering you have already started our small python app on linux, we would need to run this command:

shell
$ ssh -g -N -L ~your_interface_address~:5000:127.0.0.1:5000 localhost

This will create a non-interactive SSH tunnel, which will publish your localhost port to the interface you specify. Let's have a quick run down:

sshThe OpenSSH client program — it creates an SSH connection to a remote SSH server.

-gOption to allow remote hosts to connect to local forwarded ports. Though sometimes this can be omitted.

-N“No remote command.” Practically meaning you can end port forwarding with simple SIGINT (Ctrl + C).

-L ~your_interface_address~:5000:127.0.0.1:5000A little long one, but hang it there: we open the 5000 port to the your_interface_address, which will forward the requests to the 127.0.0.1:5000! Alas, sometimes you can't just open the port to all interfaces (0.0.0.0), so we would need to specify the one that can be accessed externally.

localhostEndpoint of our SSH session. Username will be omitted, as we are logining from our machine.

And we should be able to access our localhost application externally again.

Afterword

This way you can quickly expose your localhost applications to the outer world. While this can easy your life in home/development environments, it's not recommended to actually use it in production or heavy-load systems.
